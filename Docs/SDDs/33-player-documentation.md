## 1. Goal

A player can learn every control and every symbol on screen without leaving the game: a new **Help** page (main and
pause menus) shows a **keyboard and mouse diagram** of the live bindings, tinted by area, and a **HUD glossary** that
draws the real HUD symbols with the HUD's own shape code next to a plain explanation. Keys look the same everywhere in
the menus: the Controls page rows show **drawn key caps** instead of plain key text. A **game flag** renders the same
content into a generated `Docs/PLAYER_GUIDE.md` with screenshots, linked from the README, and a check flags a guide that
no longer matches the game. Everything is generated from the tables the game already uses (`SOLMenuText`,
`SOLKeyBindings`, `SOLConstants.h`), so the documentation cannot drift from the game.

## 8. The HUD glossary (D5, D6, D7)

### 8.1 The symbol helper

`SOLHudSymbols::Build(ESOLHudSymbol symbol, FVector2f centre, float scale, FSOLHudSymbolPrims& out)` writes the
symbol's primitives into a fixed-capacity buffer (`MAX_PRIMS_PER_SYMBOL` 32, proposed): each a kind (line, ring, arc,
box, dot, dashed line, ellipse, sample text), its points and sizes in pixels at that scale (a dashed line keeps its dash
and its gap, `DashPx` / `GapPx`, as the HUD's Canvas fallback draws both), a palette role (Primary, Secondary, Good,
Hostile, FreeLook) and an intensity. There is no Dim role: a dim element is any role at intensity
`SOL::HudPalette::DIM_INTENSITY`, as the HUD draws it (33a review). The buffer is about 2.8 KB (88 B a primitive, `static_assert` at most 3 KB; 33d-i), so callers hold one and
`Reset()` it; `Bounds` and `AddToBatch` take a caller's scratch (the prims, the card's frame output). Two replays:

- **HUD:** `ASOLFlightHud` replays the primitives through `GlowLine` / `GlowRing` / `GlowBox` / `GlowDashedLine` /
  `GlowEllipse` / `GlowDot`, so the shape renderer and the Canvas fallback both draw them as today. The draw methods
  keep what is not geometry (projection, on-screen tests, colour by state, the hint text).
- **Menus:** `SOLHudSymbols::AddToBatch(prims, batch, palette)` writes them into a `FSOLHudShapeBatch`.

Symbols with an existing builder are not re-implemented: the overlay icons and edge arrows call
`SOLOverlayIcons::AddIconShapes` / `AddEdgeArrow`, the cards `SOLHoloFrameBuild::BuildCard`, the radar plane and
stems `SOLRadar::ScopeToScreen` / `StemTop` / `ContactStyle`. **Geometry that is inline today moves into
`SOLHudSymbols` and the HUD calls it** (part 33d-i); the move is behaviour-neutral, proven by the existing HUD tests,
`-SOLSmokeHud` (reticle, Canvas fallback) and a before / after screenshot comparison.

`ESOLHudSymbol` (proposed): Reticle, Joystick, JoystickFreeLook, SteerFree, SteerHeld, SteerLocked, Prograde,
Retrograde, TargetBracket, TargetEdgeArrow, IconStar, IconPlanet, IconMoon, IconDwarf, IconAsteroid, IconRing,
IconShip, IconTarget, IconEdgeArrow, RadarScope, RadarContactAbove, RadarContactBelow, RadarSelected, GMeter,

### 8.2 Data table (D7)

`SOLMenuText::GLOSSARY_ENTRIES[]` (strings only, like `CONTROL_ROWS`):

```
struct FGlossaryEntry
{
    const TCHAR* Tab;         // One of GLOSSARY_TABS (the tab's full name)
    const TCHAR* Symbols;     // '|' list of SOLHudSymbols ids ("Prograde", "SteerFree|SteerHeld|SteerLocked"); "" = none
    const TCHAR* Sample;      // Glow text sample for a text element ("MANUAL|ASSISTED|AUTO"); "" = none
    const TCHAR* Name;        // Row heading
    const TCHAR* Description; // Body; '{<BindingId>}' = live key, '{<Token>}' = a constant (section 8.5)
};
```

`SOLGlossary` resolves each symbol id to `ESOLHudSymbol` (an unknown id is a test failure) and holds, in its `.cpp`,
the **coverage table**: for each entry the `ESOLHudLine`s, `EIconCategory`s, `ESOLHudCard`s, `ESOLSteerIcon`s and
`ESOLFlightMode`s it explains (the `UI/` enums stay out of `SOLMenuText.h`).

### 8.3 Drawing in the menu

Each glossary row's `USOLHudSymbolView` owns a small `SSOLHudShapeLayer` (`MaxShapes` `GLOSSARY_MAX_SHAPES` 128,
proposed) in **retain mode**, drawing with the solid menu subsystem's shared `M_SOLHudShape` MID (`EffectsStrength` =
the sanitized `HudEffectsStrength`, D14; `Composite` 1; view size = the layer's pixel size). The batch is built when
the view is first arranged and again only when its pixel size or the strength changes. Symbols are drawn at the HUD's
scale for a 1080-pixel canvas (`GLOSSARY_SYMBOL_UI_SCALE`, proposed), shrunk to fit the box when larger (the radar
scope, the radial menu, the cards). One custom-vertex draw per row (about 8-14 per tab). A dark backing like the HUD
panels sits behind each symbol so the additive glow reads as on the HUD.
